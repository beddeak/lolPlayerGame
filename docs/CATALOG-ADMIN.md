# 공용 선수·카드 데이터 관리 권한

`POST /players`, `/themes`, `/player-cards`, `/set-bonuses`는 이제 로그인과 별도 관리자 지정이 모두 필요하다.
일반 회원가입으로는 공용 데이터를 변경할 수 없다. 조회 `GET`은 기존처럼 공개한다.

- 토큰 없음/유효하지 않음: `401`
- 정상 로그인했지만 관리자 아님: `403`
- 명시적으로 지정한 관리자: 기존 DTO 검증 후 생성
- 관리자 계정이 삭제된 경우: 이전 토큰이 남아 있어도 `403`

## 로컬에서 API로 데이터를 추가할 때

1. 본인 계정으로 로그인한 뒤, 토큰을 넣은 `GET /auth/me`로 **본인의 기존 계정 ID**를 확인한다.
2. `backend/.env`에 `CATALOG_ADMIN_ACCOUNT_IDS=본인계정ID`를 설정하고 백엔드를 재시작한다.
   여러 관리자면 ID를 쉼표로 구분한다. 존재 여부·소유자를 확인하지 않은 ID를 미리 등록하지 않는다.
3. 해당 계정의 Bearer 토큰으로 생성 API를 호출한다.

설정이 없거나 비어 있으면 생성 API는 모든 계정에 닫혀 있다. 이번 수정은 기존 계정에 관리자
권한을 임의로 주거나 실제 `.env`를 변경하지 않는다. 권한 회수는 해당 ID를 설정에서 제거하고
백엔드를 재시작하면 된다. 별도 스키마 변경이나 마이그레이션은 필요 없다.

`npm run seed`는 로컬 DB에 직접 적용하는 기존 개발용 경로이므로 그대로 동작한다.
단순 선수 데이터 편집은 계속 `backend/data/development-seed.json`을 수정해 seed를 실행하면 된다.
이 권한 검사는 공용 카탈로그 쓰기 보호이며, 전체 배포 보안 점검을 대신하지 않는다.
