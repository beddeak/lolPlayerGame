# 구단 소식 패널과 감독 영입 제안

## 화면

시즌 허브 위쪽 **구단 소식** 버튼을 누르면 오른쪽 패널이 열린다.

- 구단 소식: 기존 운영 이벤트와 실제 완료된 계약·이적 내역.
- 이적시장: 현재 FA·협상 가능 선수. 전체 시장으로 이동 가능.
- 팬 반응: 실제 감독 평가 수치에 따른 **게임 내 가상 반응**. 실제 팬 게시물을 수집하지 않는다.
- 감독 제안: 다른 구단이 사용자 감독에게 보내는 영입 제안. 선수 영입 제안과 별개다.

기존 이벤트 큐와 다음 스플릿 미리보기 카드는 없앴다. 필수 결정은 상단에 유지한다.
리그 순위 아래에 접을 수 있는 캘린더를 배치하고, 국제대회는 그 아래에 배치한다.
캘린더는 시즌 허브에서 기본 펼침, 독립 컴포넌트에서는 기본 접힘이다.

## 감독 제안 규칙

- 기존 이적시장과 같은 **11월 19일–12월 31일**에만 생성·수락·거절한다.
- 날짜 진행으로 스토브리그에 도착하면 자동 생성한다. 이미 스토브리그인 기존 저장은
  **도착한 제안 확인** 버튼으로 생성할 수 있다. GET 조회만으로 생성하지 않는다.
- 현재 초기 정책은 같은 지역 구단을 우선하여 실제 저장에 있는 다른 구단 최대 3곳이
  시즌당 한 번 제안한다. 정교한 감독 명성·연봉·구단별 선호도 협상 모델은 아직 없다.
- 거절한 제안을 재발송하지 않는다. 한 제안을 수락하면 다른 제안은 종료된다.
- **부임 제안 수락 → 확인하고 부임**의 두 단계로 구단을 옮긴다.
- 스토브리그 기간에 경질 상태인 감독도 제안을 검토할 수 있다. 다만 시즌 중 경질 후
  날짜가 정지하는 기존 정책은 그대로이므로, 실직 상태에서 스토브리그까지 관전 진행하는
  기능은 아직 없다. 선수·구단 운영 권한을 임의로 풀지 않는다.

## 구단 이동의 데이터 경계

Career 쓰기 잠금 안에서 양 구단의 관리 플래그, 감독 소속·상태, 제안 처리를 함께 저장한다.
동시에 두 제안을 수락할 수 없다. 양 구단에 진행 중인 시리즈가 있으면 이동을 거절한다.

보존: 커리어, 선수, 현재 체결된 선수 계약, 주전·후보, 구단 예산·훈련 기록,
국내·국제대회 일정과 결과, 국제대회 등록 명단, 이전 감독 평가 기록.

정리: 이전·새 구단과 관련된 **미완료** 선수 영입·판매 협상과 해당 응답 이벤트.
이미 완료된 선수 계약을 해지하거나 선수를 같이 이동시키지는 않는다.

새 구단의 감독 평가 수치·전적은 부임 시점부터 새로 시작하고, 이전 상태는 취임 기록에 남긴다.
과거 경기·이적을 다시 평가하지 않도록 기준선을 저장한다. 이전 구단 ID를 가진 오래된
전략·선수 지시 요청은 현재 관리 구단 권한 검사로 거절한다.

## API / 저장

```text
GET  /careers/:careerId/manager/job-offers
POST /careers/:careerId/manager/job-offers/check
POST /careers/:careerId/manager/job-offers/:offerId/accept
POST /careers/:careerId/manager/job-offers/:offerId/decline
```

소유 계정만 접근할 수 있다. `manager.pendingJobOfferCount`는 유효한 대기 제안 수이며
소식 버튼의 알림 배지에 쓰인다. 뉴스는 기존 완료형 `AI_CLUB_UPDATE`로 기록되어
읽지 않아도 날짜 진행을 막지 않는다.

`CreateManagerJobOffers1789509600000` 마이그레이션은 `manager_job_offers` 테이블만 추가한다.
seed 재실행이나 기존 세이브 초기화는 필요 없다.

```powershell
cd backend
npm run migration:run
npm run schema:verify

cd ../frontend
npm run test:news
npm run test:manager-offers
npm run test:manager
npm run test:calendar
```

프론트 스크립트는 실제 컴포넌트의 SSR/핸들러와 모의 API 기반이며 브라우저의 픽셀 배치
검증을 대신하지 않는다.

## 2026-09-20 검증 결과

- 백엔드 전체 단위 테스트: 72 suites / 1,009 tests 통과.
- 실제 격리 MySQL 전체 API 테스트: 12 suites / 108 tests 통과. 빈 DB에 34개
  마이그레이션 적용과 스키마 일치를 확인했으며 실행 후 임시 DB만 제거했다.
- 프론트의 모든 `test:*` 스크립트, 양쪽 lint·타입 검사·배포 빌드 통과.
- 개발 DB에 34번째 마이그레이션 적용 후 엔티티·스키마 일치 확인.
  적용 전후 커리어 17, 구단 88, 선수/로스터 각 444, 감독 상태 5, 평가 22행 유지.
  신규 감독 제안 테이블은 0행이며 개발 세이브를 진행하거나 가상 제안을 주입하지 않았다.
- 사용자 편집 중인 `development-seed.json`은 변경·seed 실행하지 않았다.
- 실제 브라우저는 연결된 제어 대상이 없어 클릭·픽셀 배치 검증을 수행하지 못했다.

이직 관련 회귀에는 거절된 재계약 응답의 일정 차단, 기준선 기록에 가려지던 평가 조회,
Quick/Fast Sim 중간 소속 변경, 이전 구단 전략 수정 권한, 동시에 두 제안을 수락하는
요청을 포함한다.
