# PHASE 23 — AI Club (EASY)

EASY 구단이 날짜 진행에 맞춰 로스터를 평가하고, 약한 포지션 영입과 재계약을 진행한다.
Machine Learning/LLM을 사용하지 않는 규칙 기반 AI이며 능력치 보너스나 잠재력 엿보기는 없다.

## 이번 단계의 행동

- 자연 포지션이 같은 더 좋은 후보가 있으면 선발로 올린다. 빈 선발 자리도 해당 포지션 후보로 채운다.
- 평상시 7일 간격으로 전략과 영입을 검토한다. 기존 전략을 유지할 확률은 85%다.
- 전략 변경 시 현재 선수 능력치만 이용해 BALANCED / BOT_PRESSURE / BOT_CARRY 중 단순 선택한다.
- 이적시장 동안 빈 포지션 또는 가장 약한 포지션에 한 번의 영입 제안을 선택한다.
- 일반 FA 및 다른 AI 구단의 선수를 영입할 수 있다. 기존 이적료와 원소속 대체 선발 규칙을 그대로 검사한다.
- 주전 중 만료가 30일 이내로 다가온 실제 계약은 시장 개장 전에도 갱신을 검토한다.
  실제 계약 레코드가 없는 초기 주전은 오프시즌부터 순서대로 계약을 제안한다.
- 재계약은 검토당 한 명, 신규 영입은 검토당 한 건이다. 일주일 뒤 재검토할 수 있지만 같은 날짜 재호출로 반복하지 않는다.
- AI 제안도 1~3일 응답 지연과 기존 선수 의사 평가를 거친다. 수락된 제안만 계약하고, 거절/역제안이면 EASY는 협상을 종료한다.
- 계약 체결은 기존 PlayerContract / Roster / TransferRecord / 만료 이벤트 경로를 사용한다.
- 계약 확정으로 후보에 들어온 선수는 이후 로스터 평가에서 기존 선발보다 좋으면 승격한다.
- 진행 중인 시리즈가 있는 구단은 새로운 전략/로스터 검토를 보류한다. 세트 사이 고급 전술 AI는 구현하지 않았다.

현재 선수 스탯과 기존 포지션 숙련도만 판단에 사용한다. 메타 대비 훈련, 역할 숙련도 최적화,
시작 팀합 보너스는 EASY에 넣지 않았다. Player/PlayerCard 원본과 CareerPlayer 능력치를 AI 난이도로 변경하지 않는다.

## 계약 경쟁과 사용자 보호

사용자 구단 선수를 AI가 동의 없이 구매하지 않는다. 이번 자동 이적의 판매자는 AI 구단으로 제한하고,
후보 선정뿐 아니라 합의 생성과 최종 계약 확정 단계에서도 검사한다.

동일 FA에 사용자와 여러 AI 구단이 각각 제안할 수 있다. 먼저 계약이 확정되면 나머지 제안과 관련 응답
이벤트를 정리한다. AI는 사용자의 제안 내용이나 입력을 대신 수락하지 않는다.

AI가 이미 수락한 현재 이적시장 판매 합의는 자동 재계약으로 뒤집지 않는다. 해당 선수의 AI 재계약은
새로 시작하지 않고, 먼저 시작된 재계약도 최종 응답 시 판매 합의를 확인해 종료한다. 구매자 협상은 유지한다.

같은 날짜에는 자동 AI 응답을 처리한 뒤 사용자 응답을 평가한다. AI 계약으로 철회된 사용자 협상이
오래된 이벤트 객체 때문에 다시 READY가 되어 날짜 진행을 막는 것을 방지한다.

레전드 선수는 PHASE 22의 최초 경쟁 처리가 끝나기 전까지 일반 AI 후보에서 제외한다.
처리 당일에도 일반 AI가 추가 시도하지 않으며, 그다음 날 이후 아직 FA인 선수만 일반 시장 후보가 될 수 있다.
레전드 경쟁도 일반 AI와 동일한 예산 검사에 들어간다.

## 예산: 전체 재정이 아닌 AI 운용 한도

설정은 `backend/src/ai-clubs/config/ai-club.config.ts`에 모았다. 현재 초기값은 조정 가능한 프로토타입이다.

| 설정 | 초기값 |
| --- | --- |
| 판단 간격 | 7일 |
| 기존 전략 유지 | 85% |
| 선발 교체 최소 개선폭 | +2 |
| 영입 최소 개선폭 | +3, 빈 포지션은 별도 우선 |
| 만료 전 재계약 검토 | 30일 |
| 연간 급여 총액 한도 | 1,000,000만원 |
| 연간 이적료 지출 한도 | 500,000만원 |
| AI 계약 기간 | 2년 |
| AI 제안 연봉 | 기본 추정/현재 연봉 중 높은 값의 1.15배 |

연봉 한도 계산은 소속 선수의 ACTIVE 계약, 계약 없는 선수의 추정 연봉, 대기 중인 영입 제안까지 포함한다.
추정 연봉은 기존 계약 설정의 기본액 + 현재 능력치 제곱 가중치를 재사용한다. 초기 선수 다섯 명을 무료로 계산하지 않는다.
동일 선수 재계약은 기존 연봉과 새 연봉을 두 번 합산하지 않는다.

이적료는 확정 지출 + 대기 제안의 예약 이적료를 합산한다. 제안 시와 계약 확정 시 모두 예산을 다시 검사하고,
실제 서명된 이적료만 한 번 기록한다. 새 연도에 이적료 사용액을 초기화하지만 기존 연봉 의무는 유지한다.
이적료 수입을 다시 예산에 더하는 경제 순환, 사용자 구단 계좌, 월급 지급/수익/부채/명성 시스템은 아직 아니다.

## 날짜 진행과 확인 방법

캘린더 진행, Quick/Fast Sim의 기존 날짜 처리 경로에 연결했다. 별도 AI 실행 버튼을 누를 필요는 없다.
주전 교체, 전략 변경, 영입/재계약 제안과 계약 성공은 시즌 허브의 **AI 구단 소식**으로 표시된다.
AI 뉴스 및 AI 응답은 사용자 결정을 기다리는 blocking event가 아니다.

`NEXT_EVENT`의 점프 목표에서는 AI 자동 계약 응답을 제외한다. 목표까지의 날짜를 처리하면서 AI 응답은
정상 실행하지만, 사용자의 다음 계약 응답일보다 먼저 AI 응답만으로 점프가 끊기지는 않는다.

소유권 보호 조회 API:

```text
GET /careers/:careerId/ai-clubs
```

각 AI 구단의 EASY 난이도, 마지막 판단일, 현재 전략, 포지션별 평가, 연봉/이적료 한도·예약·사용액을 반환한다.
GET은 상태 생성·추첨·영입을 하지 않는다. 잠재력이나 미공개 레전드 계획도 반환하지 않는다.

## 저장 및 마이그레이션

`CreateAiClubs1788732000000`은 `ai_club_states`와 `AI_CLUB_UPDATE` 이벤트 타입을 추가한다.
구단별 상태는 실제 날짜 처리에서 처음 생성된다. 기존 커리어를 지우거나 새로 만들 필요가 없다.

```powershell
cd backend
npm run migration:run
```

새 선수 데이터는 이번 단계에서 추가하지 않는다. 기존 일반 FA와 PHASE 22 레전드 카탈로그를 사용한다.
시작 로스터가 모두 꽉 차고 보강 가능한 선수가 없다면 계약 제안 없이 기존 구단을 유지하는 것이 정상이다.
