# 주간 활동 · 국제대회 · LCP/CBLOL

## 적용 상태

코드와 마이그레이션은 작성되었고, 별도 임시 MySQL DB에서 스키마와 실제 경기 저장을 검증했다.
**개발 DB 적용 완료(2026-09-20).** 사용자의 ‘카탈로그 수정 후 DB 적용’ 선택에 따라 정식 카탈로그를 수정·검증한 뒤 마이그레이션 33번까지 반영했다.
기존 커리어/선수/구단을 재생성하거나 정식 카탈로그에 테스트 데이터를 넣지 않았다.

카탈로그 입력 파일: `backend/data/development-seed.json`.
미완성 빈 카드 2개를 사용자 요청에 따라 제거했고 T1/구단 로고 연결을 복구했다.
50명의 스탯은 사용자 첨부본을 보존했으며 Smash 20세 및 BLG·AL 나이는 이후 사용자가 지정한 값으로 반영했다.
10개 구단/50명 데이터 검사와 로고 일치 검사는 통과했다. 기존 세이브 15개와 비카탈로그 32개 테이블은 변경되지 않았다.

향후 카탈로그 수정 시 먼저 입력 검사와 전체 검증을 다시 실행한다. 반영 명령은 다음과 같다.

```powershell
cd backend
npm run seed:check
npm test -- --runInBand
npm run test:e2e:isolated
# 검증 결과 확인 후 적용
npm run migration:run
npm run schema:verify
npm run seed:catalog
```

`seed:catalog`는 카탈로그만 갱신한다. 기존 세이브에 새 구단/선수를 자동 삽입하지 않는다.
6개 지역 전체를 추가한 세계로 시작하려면 카탈로그 입력 후 **새 게임**을 만든다.
기존 세이브는 삭제되지 않는다. 팀 수 한도는 64개로 확장했다.

## 주간 활동

홈의 선발 라인업 표를 주간 활동 패널로 교체했다. 전체 선수단/선수 상세 화면은 유지한다.

- 팀 활동은 시즌 중을 포함해 매주 **스크림 또는 팀 전체 휴식 중 하나**를 선택한다.
- 개인 능력치 훈련만 프리시즌 및 준비 기간(`PRESEASON`, `BREAK`)으로 제한한다.
- 월요일~일요일 기준. 다음 월요일 자동으로 새 주를 사용한다. 조회만 해서는 DB 행을 만들지 않는다.
- 팀 스크림 주 1회: 선택 전술 숙련도 +4, 팀 케미 +3(각 최대 100), 선수 컨디션 −5, 폼 +1~2. 컨디션 0인 선수는 폼 상승 없이 제외한다.
- 주전/후보 **각 선수마다 준비 기간에 주 1회** 개인 훈련. 스크림과는 별도 예산이지만, **팀 전체 휴식과 개인 훈련은 같은 주에 병행 불가**(어느 쪽을 먼저 해도 차단).
- 개인 훈련: 선택한 기본 스탯 0~2 상승, 최대 119. 잠재력 차이에 따라 성장 확률이 달라진다.
- 훈련 컨디션 비용: 메카닉/라인전/한타 8, 나머지 기본 스탯 5~6에서 성격/나이 보정. 비용은 설정 파일을 따른다.
- 팀 휴식: 소속 선수 전체(주전·후보)의 컨디션 +20, 폼 +1~3. 현재 멘탈 능력치가 높을수록 폼 회복량이 커진다. 둘 다 최대 100.
- 컨디션 100이어도 폼이 낮으면 휴식 가능. 모든 선수의 컨디션·폼이 100이면 횟수를 소비하지 않고 거절한다. 컨디션 0이면 개인 훈련 불가.
- 팀 활동 기록 한 건에 선수별 전후 상태/실제 증감량을 JSON으로 보존한다. 기존 기록은 nullable 컬럼으로 유지하며 화면에서 회복 결과를 보여준다.
- 성장 결과는 세이브·주·선수·훈련 종류를 기반으로 결정된다. 요청 순서/반복 클릭으로 재추첨되지 않는다.
- `CareerPlayer`만 성장한다. 원본 `PlayerCard`는 바뀌지 않는다.
- 기존 날짜 없는 훈련 기록은 보존한다. 새 주간 사용량에는 합산하지 않는다.

밸런스 값: `backend/src/careers/config/training.config.ts`, `form-recovery.ts`.
`available`은 개인 훈련 가능 기간, `teamAvailable`은 팀 활동 가능 기간이다. `teamRested`와 주간 사용량을 별도로 확인한다.
휴식 POST는 이제 `/training-periods/current/team`의 `{ "type": "REST" }`이다. 기존 개인 REST 기록은 보존하지만 개인 REST 신규 요청은 400으로 거절한다.

### 폼 / 컨디션 회복

- 멘탈 0~119를 제곱 곡선으로 정규화하여 회복에 반영한다. 성격은 기존 피드백 반응에 별도로 반영한다.
- 실제 경기 한 세트 출전: 멘탈에 따른 기본 폼 +3~7에 평점(평점−5, 정수 반올림)/승패(±1) 보정을 합산(−4~+8). 저멘탈 선수의 나쁜 패배는 폼을 떨어뜨릴 수 있고, 고멘탈 선수는 더 잘 버틴다. 실제 출전 선수만 변화한다.
- 긍정 피드백의 폼 상승도 멘탈에 따라 보정하고 경기 경험 기본 상승보다 작게 제한한다. 부정적 피드백의 성격별 반응은 유지한다.
- 날짜 경과: 폼 50 미만인 선수만 멘탈에 따라 2~14일 간격으로 +1. 게임 날짜와 선수 ID에 고정된 주기로, 한꺼번에 넘기거나 나눠 넘겨도 같은 결과다. 50 이상으로 자동 상승하지 않는다.
- 날짜 진행 트랜잭션 안에서 하루당 해당 커리어 선수들을 한 번의 SQL UPDATE로 처리한다. 조회/진행 차단/같은 날짜 재조회에는 회복하지 않는다.
- **컨디션은 휴식으로만 회복**한다. 경기/스크림/개인 훈련은 소모하며, 단순 날짜 진행과 피드백으로는 증가하지 않는다. 새 선수 생성 시 초기 컨디션 100은 회복이 아닌 초기값이다.
- 원본 카드 스탯은 불변이며, 폼/컨디션은 0~100, 멘탈 등 능력치는 최대 119를 유지한다.
- 마이그레이션 `1789423200000-team-activity-effects.ts`는 활동 기록 컬럼 추가만 수행하며, 카탈로그 수정·검증 후 개발 DB에도 적용했다.
- 현재 주간 활동 선택은 사용자 구단 대상이다. AI 구단의 자동 스크림/휴식 선택은 아직 연결하지 않았으며, 장기 시즌의 AI 컨디션 소진을 막으려면 해당 정책 연결이 필요하다.

## 국제대회 사용 흐름

1. 시즌 허브에서 연간 리그 일정 연결. 자동 연결하지 않은 세이브는 수동으로 지역 시즌/국제대회를 준비할 수도 있다.
2. 같은 해의 국내 예선을 완료한다. 준비 기간에 시드가 모두 있으면 국제대회를 생성한다.
3. 사용자 구단이 진출했으면 국제대회 패널에서 현재 주전·후보 로스터를 등록한다.
4. 날짜 진행 중 경기일에 멈춘다. 시즌 허브 → 국제대회에서 **시리즈 진행**을 누른다.
5. 실제 기존 경기 시뮬레이터로 각 세트를 저장하고, 시리즈가 끝나면 다음 대진을 생성한다.

AI 구단의 국제경기도 현재는 패널에서 시리즈 단위로 진행한다. 기존 Fast Sim은 국제경기 이벤트에서 멈춘다.
각 대회의 대진·진출팀·로스터·경기 결과는 세이브별/연도별로 보존된다.
다른 계정 접근, 경기일 이전 실행, 등록 외 선수 출전, 일반 시리즈 API를 통한 우회 진행은 차단한다.
같은 경기 완료 요청을 다시 보내도 결과를 중복 기록하지 않는다.

| 대회 | 참가 | 진행 |
| --- | --- | --- |
| First Stand | 8 | 4팀 GSL 그룹 2개 → 각 2팀 → 4강/결승, BO5, 총 13시리즈 |
| MSI | 11 | 4팀 더블 엘림 플레이인 → 1팀 + 직행 7팀 → 8팀 더블 엘림, BO5, 총 20시리즈 |
| Worlds | 19 | 4팀 더블 엘림 → 1팀 + 직행 15팀 → 16팀 스위스 → 8강 싱글 엘림, 총 46시리즈 |

월즈 스위스는 3승 진출/3패 탈락, 같은 전적 대진, 재대결 금지, 첫 라운드 동일 지역 회피.
진출/탈락전은 BO3, 그 외 BO1, 녹아웃은 BO5다. 더블 엘림 결승은 브래킷 리셋 없이 진행한다.
MSI 직행은 지역 1시드 6팀 + First Stand 최고 성적을 낸 2시드 보유 지역의 2시드다.
월즈는 기본 17장에 MSI 우승팀 관련 1장과 MSI 2위 **지역** 1장을 더한다.
같은 지역끼리 MSI 결승을 치르더라도 한 지역에 5장을 중복 배정하지 않는다.
MSI 우승팀은 국내 플레이오프 참가 여부에 따라 개인 직행 자격을 유지한다.

## LCP / CBLOL

정식 예선을 위해 두 지역은 각각 **정확히 8팀**, 팀마다 유효한 주전 5명이 필요하다.
정식 국제대회는 인원이 부족하다고 2팀/4팀 대회로 축소하지 않는다. 부족한 시드/예선/로스터를 화면에 표시한다.

- LCP Split 1/2: BO3 싱글 라운드 로빈 → 6팀 하이브리드 플레이오프. 첫 라운드는 싱글 엘림, 이후 4팀 더블 엘림.
- LCP Split 3: 같은 해 Split 2 결과로 8팀 스위스 시드 → 3승/3패 → 최종 시드전 → 4팀 더블 엘림.
  4라운드의 2-0조 패자 대 0-2조 승자 교차 대진, 진출/탈락전 BO5를 반영했다.
- LCP 포인트는 결과에서 계산한다. Split 1/2 게임 득실·정규 순위·플레이오프 상위 4팀, Split 3 스위스 성적·탈락 동률 시드전·PO 3위 점수 반영.
  MSI는 Split 2 우승 + 잔여 최고 포인트, 월즈는 Split 3 결승 두 팀 + 잔여 최고 포인트 순으로 정한다.
- CBLOL Split 1: BO1 싱글 라운드 로빈 → 5~8위 플레이인 → 상위 4팀과 합쳐 6팀 더블 엘림.
  상위 2팀은 승자조 2라운드부터 시작한다. 승자조 BO3, 패자조/결승 BO5.
- CBLOL Split 2/3: BO3 싱글 라운드 로빈 → 6팀 BO5 더블 엘림.

구단/선수는 사용자가 입력하며 이번 구현에서 가짜 카탈로그 데이터는 추가하지 않았다.
테스트 안의 임시 6개 지역 선수단은 폐기되는 테스트 DB에서만 생성된다.

## 실제 규정과 게임 정책의 경계

다음 항목까지 ‘2026 규정 100% 재현’이라고 주장하지 않는다.

- 챔피언 단위 밴픽/피어리스 드래프트는 아직 없다. 기존 포지션별 챔피언 유형 기반 경기 엔진을 재사용한다.
- 공식 현장 추첨/상대 선택 대신 재현 가능한 시드 순서를 사용한다. LCP 최종 시드전은 상위 두 팀과 탈락 동률 팀을 자동 대진하며, 1위의 상대 선택 UI는 없다.
- 월즈 플레이인 네 팀: MSI 우승 지역을 제외한 지역의 최하위 시드 중 시드 번호가 큰 순, 동률은 고정 지역 순서로 선택한다. 이것은 **게임용 시드 정책**이다.
- MSI 우승팀이 국내 PO에 못 가면 그 지역의 다음 순위 팀에 자리를 준다. 국제전 성적 동률 지역도 고정 시드 순서로 정한다.
- 기존 LCK/LPL/LEC/LCS 국내 엔진은 유지한다. LPL의 별도 Championship Points/Regional Finals까지 이번에 새로 구현한 것은 아니며, 국제 진출 후보는 저장된 국내 PO 순위를 사용한다.
- CBLOL Split 1 플레이인 마지막 경기는 아래 공식 포맷 발표의 BO5를 채택했다. 추후 규정집과의 차이는 설정/대진 템플릿에서 갱신할 수 있다.
- 국내 시즌 날짜는 기존 게임 공통 달력을 유지한다(Split 3은 7월 29일 시작). 향후 연도도 2026 기반 게임 달력을 반복하며 미래 실제 일정을 보장하지 않는다.

## 구조 / 검증

- 대진 순수 함수: `backend/src/internationals/tournament-engine.ts`.
- 시드 선정: `qualification.ts`, `lcp-qualification.ts`.
- 저장/권한/실제 경기 연결: `internationals.service.ts`.
- 지역 템플릿: `leagues/regional-brackets.ts`, `leagues/lcp-swiss.ts`.
- 새 마이그레이션: 30 주간 활동, 31 국제대회, 32 LCP/CBLOL enum, 33 팀 활동 선수별 회복 기록.
- 국제대회 순수 엔진: 대회별 100개 결과 패턴 완주. 지역 브래킷은 모든 승패 조합, LCP 스위스는 500개 패턴 검사.
- 임시 MySQL에서 국제 79시리즈 실제 경기 완주, 조회 무변경/권한/등록/날짜/재요청/우회 차단 검사.
  이 테스트의 국내 예선 기록은 테스트 픽스처이며, 국내 18개 스플릿 진행은 별도 서비스 테스트로 검증한다.
- 주간 활동 E2E 15개, 새 UI 컴포넌트/요청 검사 11개. 팀 활동 배타성/주간 초기화/시즌 중 휴식/후보 선수/회복 상한/멘탈별 날짜 회복/원본 카드 불변성 검사.
- 프론트 타입/production build, 백엔드 build, 양쪽 lint 검사.
- 실제 브라우저 시각 검사는 Computer Use가 현재 URL을 안전하게 확인하지 못해 중단되었다. SSR/요청 검사를 실제 브라우저 검사로 간주하지 않는다.
- 미완성 카탈로그를 수정한 뒤 전체 단위 테스트 979개와 임시 DB 통합 테스트 100개가 통과했다. 실패하던 검사나 검증 규칙은 제거하지 않았다.
