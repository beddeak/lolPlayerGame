# PHASE 19 — 계약과 재협상

커리어에 속한 선수의 계약은 원본 `Player` / `PlayerCard`와 분리해 저장한다.
이번 단계에서는 감독 소속 구단의 주전·후보 선수와 계약 및 재계약을 체결한다.
다른 구단 선수의 이적, FA 영입, 계약 만료에 따른 소속 변경은 PHASE 20에서 연결한다.

## 사용 흐름

1. 구단 화면 또는 상단의 **계약** 메뉴에서 선수를 고른다.
2. 연봉, 기간, 예상 역할, 주전 보장과 약속을 입력하고 제안한다.
3. 시즌 허브에서 날짜를 진행하면 1~3일 뒤 선수 답변에서 시간이 멈춘다.
4. 계약 화면에서 수락, 재협상, 조건 유지, 철회, 답변 시간 요청을 선택한다.
5. 계약 확정 후 계약서와 약속이 저장되고 날짜 진행을 재개할 수 있다.

연봉 입력 단위는 **만원/년**이다. 예를 들어 `100000`은 연봉 10억 원이다.
기간은 1~5년이다. 이 범위와 선수 평가 계수는 `backend/src/contracts/config/contract.config.ts`에서 조정한다.
현재 연봉 산정은 게임 테스트를 위한 임시 밸런스이며 실제 선수 연봉을 나타내지 않는다.

## API

모든 경로는 Bearer 로그인과 해당 커리어 소유권을 검사한다.

| 메서드 | 경로 | 기능 |
| --- | --- | --- |
| GET | `/careers/:careerId/contracts` | 확정된 현재 계약 |
| GET | `/careers/:careerId/contracts/offers` | 제안·선수 응답·협상 이력 |
| POST | `/careers/:careerId/contracts/offers` | 새 제안 |
| POST | `/careers/:careerId/contracts/offers/:offerId/respond` | 감독 결정 |

제안 예시:

```json
{
  "careerPlayerId": 1,
  "terms": {
    "annualSalary": 100000,
    "years": 3,
    "starterGuarantee": true,
    "expectedRole": "CORE",
    "promises": [
      { "type": "STARTER_GUARANTEE" },
      { "type": "CARRY_ROLE" },
      { "type": "SIGN_POSITION", "position": "SUPPORT" }
    ]
  }
}
```

감독 결정은 `{ "action": "ACCEPT" }`처럼 전송한다.
`COUNTER`에는 제안과 동일한 전체 `terms`를 함께 보내야 한다.

## 응답과 결정

- 제안은 `WAITING_PLAYER_RESPONSE`로 저장된다. 응답 날짜는 제안 ID와 협상 차수로 정해지며 조회 시 달라지지 않는다.
- 달력/시뮬레이션의 기존 일자 처리 중 평가한다. 선수 능력, 현재 연봉, 감독 신뢰, 성격, 팀 전력, 역할과 팀 보강 약속을 반영한다. 아직 없는 감독/구단 명성이나 타 구단 제안을 실제 데이터인 것처럼 사용하지 않는다.
- 응답은 `PLAYER_ACCEPTED`, `COUNTER_OFFERED`, `REJECTED` 중 하나다. 거절도 확인·재협상할 수 있도록 감독 결정을 기다린다.
- `ACCEPT`는 선수 수락 조건 또는 선수 역제안 조건을 확정한다.
- `COUNTER`는 수정한 조건을, `KEEP`는 기존 조건을 다시 검토하게 한다. 새 응답까지 다시 1~3일이 걸린다. 거절된 조건의 단순 유지는 불가능하다.
- `REQUEST_TIME`은 결정 날짜를 2일 미루며 기존 선수 응답을 유지한다. 전체 협상 중 1회 사용할 수 있다.
- `WITHDRAW`는 검토 중에도 가능하며 관련 이벤트를 함께 완료한다.
- 기본 최대 검토 차수는 5회다. 제한은 설정 파일에 모여 있다.
- 계약 응답 이벤트는 일반 이벤트의 `resolve` API로 건너뛸 수 없다.

## 계약·약속 저장

`contract_offers`는 제안 및 협상 이력을 보관하고, `player_contracts`는 선수별 현재 계약을 보관한다.
재계약 확정 시 현재 계약을 갱신하되 과거 `SIGNED` 제안과 협상 이력은 유지한다.
계약은 확정한 게임 날짜부터 즉시 적용된다. 종료일은 계약 연수 뒤 기념일의 전날이다.
윤년 2월 29일의 기념일은 해당 연도의 2월 말로 보정한다.

주전 보장은 `CORE` 또는 `STARTER` 역할에서만 설정할 수 있다.
주전 보장 약속에는 주전 보장 체크가, 캐리 역할 약속에는 `CORE` 역할이 필요하다.
특정 포지션 영입 약속에는 포지션이 필요하며 중복 약속은 거절한다.
약속은 계약에 `PENDING`으로 저장한다. 이번 단계에서 선수 교체나 신뢰 하락을 자동으로 적용하지 않는다.
약속 이행 판정·불만·이적 요청은 시즌/이적 시스템의 실제 결과와 연결할 후속 작업이다.

## 일관성과 검증

계약 쓰기와 응답 처리는 커리어 잠금을 통해 날짜 진행과 직렬화된다.
한 선수에게 열린 협상은 하나만 허용하고, 선수별 현재 계약은 DB 고유 제약으로 보호한다.
계약 확정과 이벤트 완료는 같은 트랜잭션에 포함된다.
오래된 응답 이벤트는 협상 차수 및 이벤트 ID로 구분해 현재 제안을 덮어쓰지 못한다.

```powershell
cd backend
npm run build
npm test -- --runInBand
npm run test:e2e:isolated
npm run migration:run
npm run schema:verify
```

격리 E2E는 임시 MySQL DB를 만들고 전체 마이그레이션, 스키마 일치, API 흐름을 검사한 후 임시 DB를 삭제한다.
일반 개발 DB에는 마지막 두 명령으로 새 테이블을 반영한다. 기존 계약이 없던 선수에게 임의의 연봉 계약을 자동 생성하지 않는다.

2026-09-09 검증: 백엔드 단위 테스트 35개 묶음 / 210개 테스트, 격리 MySQL E2E 2개 묶음 / 9개 테스트 통과.
양쪽 빌드 및 변경 파일 린트 통과. 개발 DB에 계약 마이그레이션을 적용했고 스키마 일치 검사도 통과했다.
컴퓨터 제어 연결 오류로 실제 브라우저 클릭·시각 검증은 수행하지 못했다.
