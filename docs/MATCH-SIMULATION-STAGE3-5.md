# 경기 시뮬레이션 v2 — STAGE 3–5 개발 코어

2026-09-28: 사용자 요청으로 실제 경기의 기본 엔진에 연결했다. 현재 연결·저장·관전 상태와 적용 절차는 [STAGE 6](MATCH-SIMULATION-STAGE6.md)을 참고한다. 아래 opt-in 경계는 최초 STAGE 3–5 작업 당시 기록이다.

작업 기준: 2026-09-27. 사용자가 승인 대기 없이 이어서 구현하도록 지정한 범위다.

후속 **운영 AI 보완**은 [MACRO-AI-REVIEW.md](MACRO-AI-REVIEW.md)에 기록한다. 아래 STAGE 3–5 최초 검증 수치/해시는 당시 `tactical-core-2`의 이력이며 현재 버전의 결과와 구분한다.

## 적용 경계

- **개발 전용 opt-in 코어다. 기존 커리어 경기 결과/API/화면/DB를 교체하지 않는다.**
- `createEngineInput({ ..., battle: true })`가 `CLASSIC_SR_26_1_BATTLE_APPROX_V2`를 선택한다. 기존 10분 lab rules는 별도로 유지한다.
- 스냅샷에는 엔진·Ruleset·맵·실제 챔피언 카탈로그·밸런스·중립 메타를 고정한다. 현재 챔피언 173개와 모든 포지션 자유 배치는 유지한다.
- 선수 원본 능력치 0–119, 현재 폼/컨디션과 경기 중 HP/골드/레벨은 서로 다른 상태다. 개발 코어가 커리어 원본 능력치를 변경하지 않는다.
- `FINISHED`는 실제 적 넥서스 HP가 0이 되었을 때만 가능하다. 시간 제한 도달은 `HORIZON_REACHED`이며 승자를 만들지 않는다.
- 새 엔진을 사용하지 않는 기존 경기/저장 기록에는 새 규칙을 소급 적용하지 않는다.
- 현재 엔진 버전은 `tactical-core-3`다. 이전 `tactical-core-2`/`tactical-lab-1` 개발 체크포인트는 버전 불일치로 거절한다. 이것은 실제 커리어 세이브 형식을 변경하는 작업이 아니다.

## STAGE 4: 같은 판정기에서 전투와 종료

주요 모듈: `simulation-v2/effects.ts`, `engine.ts`, `battle-planner.ts`.

- 카탈로그의 챔피언 분류에서 **게임용 공격·제어·보호·재배치 행동 슬롯**을 만든다. 실제 챔피언 Q/W/E/R 또는 173개 스킬 전체를 복제했다는 의미가 아니다.
- 사거리·시야·HP·마나·쿨다운·시전 시간·투사체·CC·보호 상태는 실제 시간 흐름과 공통 판정기에 연결한다.
- 이동은 경로와 이동 속도를 소비한다. 합류 계획이 생겼다는 이유로 원거리 아군의 피해를 즉시 더하지 않는다.
- 동시 국소 교전은 서로 독립적으로 진행할 수 있다. 사망·이동·철수·귀환·상태 만료는 같은 월드 시간 기준이다.
- 오브젝트/공성/사이드/기지 방어는 관측 기반 행동 후보다. 목표가 없어지거나 합류 불가/수적 열세가 관측되면 재평가한다.
- 마지막 승패 추첨, 팀 OVR 후처리, 시간 초과 강제 승자는 없다.
- **Flash/Teleport는 미지원.** 소환사 주문은 현재 정글 Smite 근사 모델만 연결한다. 마나 역시 공통 자원 모델이며 에너지/무자원 챔피언을 완전히 구분하지 않는다.
- 재배치 슬롯은 시전 시간과 실제 경로 이동/일시 가속으로 구현한다. AI의 모든 상황별 스킬 조합·카이팅·추격 판단까지 완성한 것은 아니다.

## STAGE 5: 전술·숙련도·메타 소비 위치

`tactics.ts`는 승률이나 피해량을 반환하지 않는다. 관측 기반 계획기의 선호도와 제한된 조율 값을 반환한다.

| 원본 | 계산/경계 | 적용 대상 | 중복 금지 |
| --- | --- | --- | --- |
| 선수 Mechanics/GameSense/Laning, 폼/컨디션/피드백 | 기존 `input-adapter.ts`의 execution, 최종 0–1.19 | 공통 전투 실행 모델 | 팀 OVR/최종 승률에 다시 곱하지 않음 |
| 포지션 숙련도 | execution에서 `.6 + .4 × proficiency/100` | 해당 세트 수행 | 전술 어댑터에서 재적용하지 않음 |

### 중립 메타

- `NEUTRAL_TACTICAL_V1`: 라인·오브젝트·시야 환경 효율은 모두 1이다.
- 시리즈 환경 및 세트 입력 해시에 포함한다.
- 지원되지 않는 비중립 버전/가중치는 명시적으로 거절한다. 미래 메타 카탈로그를 준비된 기능처럼 활성화하지 않는다.
- 감독 전술과 메타는 별개다. `BOT_CARRY`가 중립 메타라는 이유로 보너스 OVR을 받지 않는다.

## BO3/BO5와 실제 챔피언 피어리스

주요 모듈: `simulation-v2/series-lab.ts`. 기존 `drafts/draft-state.ts`의 선택권·밴픽·배치 함수를 재사용한다.

```text
createSeriesLab
  → beginSeriesDraft (그 세트의 선발/전술/폼/컨디션 스냅샷)
  → selectForSeries / draftForSeries / assignForSeries
    또는 autoDraftSeries
  → prepareSeriesGame (합법 드래프트 재검증 + 입력/환경 고정)
  → startSimulation / runUntil (같은 실제 경기 코어)
  → completeSeriesGame (종료 증거 확인 후 시리즈 JSON만 전진)
```

- 첫 세트는 기존 대회 정책에서 해결한 `FirstSelection`을 받는다. 일반 추첨·플레이오프 상위 시드·승자조·LCP 2v2를 새 코어가 임의로 대체하지 않는다.
- 이후 세트 선택권은 직전 패자다. 물리적 블루/레드 진영과 선픽/후픽은 독립적으로 선택한다.
- 일반 밴은 해당 세트에만 적용한다. 양 팀이 **실제로 픽했던 챔피언 ID만** 시리즈 누적 피어리스 제한으로 이월한다.
- 같은 유형/추천 포지션 전체를 막지 않는다. 다섯 세트라면 50개의 중복 없는 실제 픽을 사용한다.
- 입력/드래프트 상태를 바꾸거나 이전 세트 응답을 다시 제출하면 거절한다. 세트 종료를 중복 반영하지 않는다.
- 준비 시 선택권·밴·픽·배치를 포함한 드래프트 해시를 고정한다. 누적 피어리스 픽은 변경 가능한 UI 목록이 아니라 실제 고정 경기 입력의 10명에서 가져온다.
- 결과는 `FINISHED`, 올바른 고정 입력, 실제 상대 넥서스 파괴 상태·사건·피해 기록을 모두 요구한다. 시간 초과/부분 실행/오류는 시리즈를 진행시키지 않는다.
- 새 세트의 HP/골드/레벨/쿨다운은 새 월드에서 시작한다. 폼/컨디션/피드백은 세트 사이에 명시적으로 전달한 스냅샷만 받는다.
- 커리어 트랜잭션/계약/영구 성장 기록에 저장하는 기능은 아직 붙이지 않았다.

## 검증 기록

`series-lab.spec.ts`의 다섯 세트 검사는 **합법 드래프트/스냅샷/결과 수납 프로토콜 검사**다. 빠른 단위 테스트에서 만든 명시적 terminal receipt fixture를 사용하며, 실제 40분 경기를 다섯 번 완주한 결과나 승률 균형 검사로 해석하면 안 된다. 실제 Resolver의 넥서스 파괴와 장시간 운영은 별도 시나리오/실행 검증으로 구분한다.

주요 회귀 범위:

- 팀 전술이 안전한 공성/이동 후보에 반영되고, 숨은 적 HP·현재 좌표 변경으로 계획이나 RNG가 달라지지 않는다.
- 와드 충전/시전/만료·탐지, 포탑의 설정 시야/공격 사거리/벽 차폐, 자원·쿨다운·CC·보호막·투사체를 검사한다.
- 두 지역의 동시 사망, 보호막 피해의 실제 HP 지표, 버프와 무관한 고정 Smite 피해, 동일 보상 중복 금지, 구조물 선행 조건과 넥서스 종료를 검사한다.
- 유충·전령의 잘못된 재생 설정, 소수 골드 분배, 누락/문자열/무한대 퀘스트 목표와 잘못된 Ruleset을 실행 전에 거절한다.
- 드래프트/입력/환경 불일치, 세트 완료 중복, 미완료 결과, 직전 패자 선택권, 5세트 50픽 피어리스와 밴 초기화, JSON 복구를 검사한다.

### 발견 후 수정한 문제

- 보유 골드가 다음 아이템 가격보다 적은데 반복 귀환하던 조건, 기지에서 재귀환하여 회복을 막던 조건.
- 다른 라인 웨이브를 자신의 공성 웨이브로 오인하던 조건과, 탑/바텀 미니언이 포탑 사거리 직전에서 지나치던 이동.
- 불리한 오브젝트를 포기하고 교환하려는 계획이 뒤 로직에서 덮이던 조건.
- 보호막에 막힌 공격이 포탑 어그로를 만들지 않던 조건 및 포탑 사거리/팀 시야 불일치.
- 와드 설치와 다른 시전을 겹쳐 실행하는 경우, Smite에 일반 피해 변동/버프를 중복 적용하는 경우.
- 세트 입력은 고정되었는데 별도 드래프트 목록 변경으로 피어리스 기록이 어긋나는 경우.

### 탐색 비용과 성능 경계

`UnitSpatialIndex`는 이동/공격 스냅샷마다 생성하는 내부 가속 자료구조다. 원본 순서·거리 경계·유닛 참조를 유지하고 사거리/생존/진영/시야/구조물 선행 조건 검사를 대체하지 않는다. 체크포인트에 인덱스나 캐시를 저장하지 않는다.

포탑 시야 수정 전 같은 고정 입력(seed 125)의 53.9567분 경기에서 전체 검색과 인덱스 검색의 전체 상태 해시 `14eea8a987b34906b4c405e79ff9dff39b981e146f06b36e207bf60e8757ec79`, 보상 원장 해시 `78805eb64f7f671102c0d7b379ca4726aa735c049e5e713f26f8c5d27cbdfa1e`가 같았다. 관측된 실행 시간은 약 84.8초→47.1초였으나 동시 빌드/테스트 부하가 달라 엄밀한 속도 배율 벤치마크는 아니다. 이후 시야 동작 수정으로 최종 경기 해시/진행은 달라질 수 있다.

일부 조합은 60분까지 종료되지 않는 사례가 확인되었다. 이 상태를 임의 승자로 처리하지 않는다. **다양한 조합의 종료율·경기 길이·승리 경로·후반 AI 균형을 더 검증해야 하며, 프로덕션 전환 완료로 보지 않는다.**

### 개발용 실제 시리즈 실행

백엔드 폴더에서:

```powershell
npm run sim:battle -- --seed 125 --minutes 60 --verify-resume
npm run sim:series -- --seed 125 --minutes 60 --best-of 5
```

`--verify-resume`를 더하면 각 세트의 초기 체크포인트부터 다시 실행해 전체 상태가 같은지 확인한다(추가 CPU/메모리를 사용한다). `--minutes`는 **세트별 최대 실행 시간**이며 1–60, `--best-of`는 1/3/5다.

- 실제 드래프트→새 경기 엔진→넥서스 결과 수납 흐름이다. 경기 결과를 주입하지 않는다.
- BO5는 먼저 3승한 팀이 있으면 끝난다. 검증을 위해 일부러 2:2를 만들거나 5세트를 강제로 실행하지 않는다.
- 한 세트라도 넥서스 종료 전에 시간 제한에 도달하거나 엔진 오류가 생기면 `INCOMPLETE`로 멈춘다. 다음 세트를 시작하지 않는다.
- CLI에는 테스트용 팀/선수와 결정적 추첨을 사용한다. 기존 실제 대회의 시드 정책을 조회하거나 커리어 상태를 바꾸지 않는다.
- 짧은 1분 검사는 의도적으로 `INCOMPLETE`가 나오는 종료 경계 테스트다. 이 경우 CLI 자체의 종료 코드는 2이며 구현 예외는 1이다.
