# 협곡 관전 시제품 03

## 보는 방법

- 시즌 허브 → 일정 진행 패널의 `협곡 관전 데모`: 현재 구단과 다른 구단의 주전으로 가상 경기 재생. 새로 열 때마다 다른 시드로 경기 길이·전개·승자를 선택한다. API 호출/세이브 수정 없음. `처음부터`는 현재 데모를 그대로 다시 재생한다.
- 밴픽 배치 확정 → 경기 시작: 기존 서버가 세트를 한 번 계산/저장한 뒤 관전 화면, 이후 기존 결과창으로 이동.
- 세트별 결과의 `N세트 협곡 다시보기`: 이미 저장된 경기 재구성. 다시 경기 계산하지 않음.
- 8/16/32배속, 일시정지, 처음부터, 시간 탐색, 결과 바로 보기. 다른 탭은 자동 일시정지.

## 정확성 경계

이것은 실시간 전투 엔진이 아닌 **기록 기반 관전 연출**이다. 결과에 맞춰 킬/데스 및 가능한 어시스트를 배정하고 선택한 챔피언 초상화를 표시한다. 승패는 기존 서버 결과가 유일한 기준이다.

서버에 초 단위 로그가 없으므로 이동 경로, 교전 위치/시간, CS·경험치·레벨·체력, 미니언, 타워/드래곤/바론은 관전용 재구성이다. 이 값들은 실제 저장 경기 지표가 아니다. 화면에 명시한다. 데이터가 맞지 않는 과거 기록은 경고를 표시하며 결과를 보정/저장하지 않는다.

데모는 현재 주전 이름으로 만든 별도 가상 지표이며 선수 능력이나 실제 예상 승률을 평가하지 않는다. 실제 세트에 대한 난수는 matchId 기반으로 고정한다. 관전/다시보기는 경기 상태·계약·폼·컨디션·피드백을 변경하지 않는다.

## 경기 흐름 (게임용 관전 규칙)

- **0~15분**: 탑·미드·바텀 라인 유지, 미니언 웨이브 충돌/파밍, 정글 캠프 순회. 초반 킬은 같은 라인과 정글만 참가하는 최대 4명 소규모 교전이다. 집계 어시스트를 맞추려고 5명 전원을 불러오지 않는다.
- **15분 이후**: 사이드 운영과 오브젝트 교전. 드래곤/바론 장면 사이에는 라인 관리 시간이 있고, 바론은 20분 이전에 등장하지 않는다. 이는 공식 패치 규정 복제가 아닌 시제품용 흐름이다.
- **공성**: 한 라인의 1차 → 2차 → 억제기 포탑 → 억제기 → 넥서스 포탑 2개 → 넥서스. 선행 건물 보호, 건물별 체력/공격 연출, 생존 공격자 확인. 전멸 시 복귀할 때까지 공성이 늦춰진다. 수비 팀도 기지로 합류한다.
- **승리 경로 5종**: 미드 집중 공성 / 사이드 스플릿·양쪽 압박 / 오브젝트 후 라인 전환 / 끊어먹기·빈 라인 돌파 / 기지 방어 후 역전. 탑·미드·바텀 캐리를 개별 비교하며 정글·서포터 인원 수를 바텀 점수로 더하지 않는다. 바론 없이 끝나는 경기와 서로 다른 바론 타이밍이 있다. 양쪽 압박에서는 두 번째 라인의 포탑도 공략하고, 역전 경로에서는 패배 팀이 먼저 더 깊이 전진한다.
- **갱킹**: 아군 라이너의 동선·생존·어시스트 여유를 확인해 호응자를 먼저 배정한다. 역갱으로 정글러가 죽는 경우도 남겨두며 갱킹 100% 성공을 강제하지 않는다. 양쪽 모두 공격을 표시한다.
- **CS·레벨**: 파밍할 수 있는 시간에 역할별 CS와 경험치를 얻고 처치/어시스트 경험치를 더해 최대 18레벨까지 성장한다. 사망·귀환·우물·이동·교전 중에는 CS를 얻지 않는다. 서포터는 낮은 CS와 공유 경험치를 사용한다. 레벨은 최대 체력·교전 피해 보정·부활 시간에 연결된다. 정식 Riot 패치 수치를 재현한 것이 아닌 관전용 규칙이다.
- **체력**: 교전이 끝나도 누적 체력을 유지한다. 처치나 레벨업 자체는 체력을 채우지 않는다. 비전투 12초 후 느린 자연 회복, 체력이 낮을 때 8초 귀환 후 우물 회복, 사망 후 부활만 회복 경로다. 교전 예정이 임박했거나 공성 중이면 귀환을 시작하지 않는다.
- **부활**: 사망 순간 레벨과 경과 시간으로 대기 시간을 확정하고 지도·선수 패널에 남은 초를 표시한다. 부활 후 복귀 시간도 적용한다.
- **승리**: 단순히 타이머가 끝났다고 승리하지 않는다. 넥서스까지 유효한 파괴 경로가 완성돼야 승리 연출을 표시한다.
- 죽은 선수와 복귀 중인 선수에게 어시스트를 억지로 주지 않는다. 과밀하거나 모순된 과거 지표는 일부 장면을 생략하고 경고하며, 실제 최종 지표는 기존 결과창이 기준이다.
- 선수 동선은 속도 제한된 경로를 한 번 계산해 재사용한다. 포탑 하나가 깨질 때마다 중앙 라인으로 돌아가는 움직임을 없애고 다음 건물로 진격한다.
- 18분 미만의 과거 경기는 이 단계 모델에 맞지 않으므로 관전을 생략하고 기존 결과창을 사용한다.

독립적인 전투 AI, 챔피언별 스킬·사거리·정글/미니언 피해 판정, 실시간 행동으로 승패가 결정되는 서버 엔진은 아직 아니다. 현재 단계는 저장된 결과를 바꾸지 않고 납득 가능한 과정을 보여주는 관전 재구성이다.

## 구현

- `frontend/src/match-spectator.ts`: 순수 재구성/프레임 계산/데모 생성.
- `frontend/src/match-spectator-progression.ts`: 한 번만 계산하는 초 단위 체력·CS·경험치·레벨·귀환·사망 상태. 탐색/다시보기로 수치가 중복 증가하지 않는다.
- `MatchSpectator.tsx/css`: SVG 협곡, 10명 이동/처치/부활, 킬 로그, 재생 컨트롤.
- 지도·포탑·선수·미니언이 같은 900×900 좌표/라인 경로를 공유한다. 탑·바텀 길이는 대칭이며 기지 좌표는 동결해 애니메이션에 의한 지형 변형을 막는다.
- 고정 지형 요소는 재사용하고 재생 시계는 최대 20Hz. 숨겨진 탭/일시정지/종료/언마운트에서 타이머 정리.
- 기존 경기 저장 및 재시도/idempotency 흐름 유지. 경기 서버/DB 스키마 변경 없음.

검증: `npm run test:spectator`는 63개 경기 흐름(서로 다른 시드·22/30/40분·무킬), 5개 경로/3개 공략 라인, 바론 생략/시간 변동, 갱 호응자의 실제 위치와 역갱, 킬 이후 비율/절대 체력 회복 금지, CS/레벨 성장과 사망·귀환 중 파밍 금지, 부활 시각, 좌표 대칭·불변, 공성 보호와 재생 컨트롤을 검사한다. `test:match-flow`, `test:match-report`, `test:theme`와 전체 프론트 테스트, lint/build도 함께 사용한다. 브라우저 실측/실시간 전투 판정과 구분한다.
