# 경기 시뮬레이션 STAGE 6 — 실제 경기 연결

2026-09-28. `lol_match_simulation_rework_v2_reviewed.md`의 STAGE 6 구현 기록이다. 사용자가 새 엔진을 실제 경기의 기본 계산기로 연결하도록 지정했다.

## 변경된 실행 경로

`MatchesService.simulate → TacticalRunsService → buildCareerEngineInput → startSimulation/runUntil → projectMatch → adaptTacticalResult → 기존 경기·선수 상태 저장`을 사용한다. 일반 경기와 Direct/Quick/Fast의 공통 경기 서비스에서 같은 코어를 호출한다. 이전 승패 추첨과 합성 스탯 생성기를 새 경기 결과에 호출하지 않는다.

- 실제 넥서스 파괴로 `FINISHED`가 된 경기만 승자·스탯·경기 후 컨디션을 확정한다.
- `HORIZON_REACHED` 또는 코어 오류는 결과/커리어 보상을 만들지 않는다. 입력과 상태를 진단 가능하게 보존한다. 기존 코어의 일부 조합이 60분에 끝나지 않는 한계는 남아 있다.
- 기존 완료 경기 결과와 과거 관전 경로는 보존한다. 새 엔진의 과거 경기 재계산은 하지 않는다.
- 시리즈는 기존 밴픽·선택권·누적 피어리스 저장 경로를 사용한다. 자동 진행에서는 같은 밴픽 AI에 결정을 위임한다. 감독이 직접 진행하는 밴픽/세트 경계는 유지한다.
- 단독 경기 역시 실제 10개 챔피언을 합법적으로 자동 드래프트한다. 지원하지 않는 진행 중 구형 가상 픽 카탈로그는 명시적으로 거절한다.

## 저장·재접속

추가 테이블은 `match_tactical_runs`, `match_tactical_chunks`다. 실행권/입력/체크포인트와 결과 경기의 연결을 분리하여 경기 계산 동안 긴 DB 트랜잭션을 유지하지 않는다.

- career/series/game 기반 실행 키, DB 고유 제약, 커리어 잠금과 실행 lease로 중복 실행·최종 반영을 보호한다.
- 엔진/룰셋/카탈로그/입력과 seed, RNG·사건 원장을 포함한 체크포인트를 고정한다. 재요청은 저장된 입력으로 이어진다.
- gzip 체크포인트는 60초의 경기 시간마다 저장한다. 코어는 경기 시간 1초 구간마다 이벤트 루프를 양보한다. 프로세스당 한 개 실행으로 메모리 사용을 제한한다.
- 최종 경기·스탯·선수 컨디션 변경과 run의 match 연결은 같은 트랜잭션에서 확정한다. 이미 연결된 실행은 선수 상태를 다시 갱신하지 않는다.
- 계산 중이거나 결과 반영을 기다리는 경기가 있으면 같은 커리어의 선수/날짜/피드백 변경을 차단한다. 같은 세트의 재개·최종 반영만 해당 실행 키로 허용한다. 재개 준비 중에는 날짜 이벤트나 리그 준비에 따른 변경을 반복하지 않는다.
- Fast 재시도는 이미 시작한 경기를 먼저 재개한다. AI 경기는 처리 한도에 포함하고, 감독 팀은 고정된 한 세트만 마친 뒤 다음 의사결정 지점에서 멈춘다. 다른 경기나 잘못된 세트 번호로 실행권을 재사용할 수 없다.
- 리플레이 조회는 기존 계정/커리어 소유권을 확인한다. 클라이언트가 입력·체크포인트·경기 중 명령을 제출하는 API는 추가하지 않는다.

API는 `GET /matches/:id/tactical-run`, `GET /matches/:id/tactical-run/chunks/:index`다. 완료 경기 DTO의 `tacticalReplay`가 새 관전 화면 연결을 지정한다. 과거 경기는 이 필드가 없다.

## UI·리포트

`replay.ts`는 실제 프레임과 같은 사건/보상 원장을 순회해 시점별 KDA·획득 골드·지갑·CS·피해·아이템을 만든다. 원래 사건 sequence를 유지하며 내부 공격/자연 골드 사건을 모두 브라우저에 보내지 않는다. 각 청크는 최대 256 KiB다.

`TacticalMatchViewer`는 필요한 구간만 조회하고 최대 세 청크를 캐시한다. 재생 커서는 커리어/경기/엔진/입력 해시별로 분리된다. 탭이 숨겨지면 재생이 멈추고 배속·탐색은 서버 계산을 호출하지 않는다. 지도·체력·지표·중계는 동일한 마지막 저장 프레임 시점까지만 표시한다.

현재 스냅샷은 2초 간격이다. 두 프레임 사이의 실제 경로 변경/CC를 알 수 없으므로 임의 직선 보간 대신 마지막 확정 위치를 유지한다. 따라서 부드러운 연속 이동은 아직 구현하지 않았다. 관전은 전지적 시점이며 AI 관측과 별개다.

최종 승자/리포트는 재생 종료 시점에 표시한다. 실제 골드의 소수점은 저장하고 GD@15/CSD@15는 15분 전에 종료하면 `null`/`—`로 보존한다. 경기 평점과 경기 후 컨디션 갱신에는 기존 표시/커리어 함수를 사용하되 그 값으로 승패나 원장 수치를 다시 생성하지 않는다.

이전 최종 승률 공식의 전략·메타·세트 보너스 가산값은 새 코어에 중복 적용하지 않는다. 현재 새 코어의 중립 메타, 근사 스킬/아이템, 미지원 기능 범위는 [STAGE 3–5](MATCH-SIMULATION-STAGE3-5.md)와 [환경 모델](TACTICAL-ENVIRONMENT-MODEL.md)을 따른다. 활성 세트 보너스와 원래 선수 상태는 스냅샷에 보존하지만 이전 합성 엔진의 세트 보너스 효과 전부를 실제 행동 모델로 옮긴 것은 아니다.

## 실행 환경 적용

기존 배포 환경의 `backend/.env`와 DB 연결을 준비한 뒤 `npm.cmd run migration:run`, `npm.cmd run schema:verify`를 실행하고 서버를 다시 시작해야 한다. `synchronize`와 자동 마이그레이션은 계속 꺼져 있다.

이 작업 공간에는 `.env`, DB 연결 환경변수, MySQL/Docker 실행 도구가 없어 실제 DB 마이그레이션과 DB E2E는 실행하지 못했다. 개발/사용자 DB를 초기화하거나 변경하지 않았다. 마이그레이션은 기존 경기 스탯을 보존하는 형식 확장과 새 테이블 추가이며, 되돌릴 때 소수점/미관측 지표가 손실되는 경우 명시적으로 중단한다.
