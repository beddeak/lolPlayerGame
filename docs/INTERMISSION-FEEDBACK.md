# 세트 사이 피드백

결과 화면에는 기존 경기 결과와 하단 세트 지표만 표시한다. BO3/BO5에서 `N세트 넘어가기`를 누르면 별도의 피드백·전술·교체 화면이 열리고, 여기서 `N세트 밴픽 시작`을 눌러야 다음 밴픽이 시작된다. 결과로 돌아왔다가 다시 열어도 저장한 피드백 횟수는 유지한다. BO1 및 시리즈 종료 후에는 입력하지 않는다.

- 피드백은 **선택 사항**이다. 아무것도 전달하지 않고 다음 세트로 진행할 수 있다.
- 각 세트 사이에 팀 전체 최대 1회, 개인 선수 1명에게 최대 1회. 개인 피드백은 다섯 명 각각에게 한 번씩 주는 방식이 아니다.
- 대상은 직전 세트에 내 구단으로 출전한 선수. 팀 피드백도 다섯 명의 반응을 개별 계산한다.
- 밴픽 시작 후 피드백, 선발 교체 및 팀 전술 변경은 잠긴다. 전술/선발은 다음 밴픽 이전에 조정한다.
- 성격, 멘탈, 감독 신뢰, 현재 폼, 직전 승패와 개인 평점을 반영한다. 수용 성향은 현재 성격과 신뢰에서 계산하며 임의의 새 카탈로그 스탯을 만들지 않는다.
- 감독 신뢰 변화만 장기 저장한다. 멘탈/폼/자신감/동기/부담/공격성/위험 감수/캐리 보정 및 팀 분위기는 **바로 다음 세트 한정**이다. 캐리 보정은 실제 캐리 임무/전술일 때만 적용한다.
- 다음 세트에 벤치로 내려간 선수의 효과는 적용되지 않으며, 나중에 다시 출전한다고 이월하지 않는다. 컨디션이나 기본 능력치를 직접 회복시키지 않는다.
- 일시 효과는 승패 계산, 선수 경기 지표에 반영하며 경기 기록에 스냅샷으로 남긴다. 기존 버전의 영구 반영된 피드백에는 일시 효과를 재적용하지 않는다.

## 안전 장치

`POST /match-series/:id/feedback`에 `afterGameNumber`를 보내 오래된 화면의 입력을 거절한다. 커리어 쓰기 잠금과 `(seriesId, afterGameNumber, type)` 유일 인덱스로 중복 및 동시 입력을 제한한다. 시뮬레이션 저장 직전 피드백 목록도 확인한다.

응답이 유실되면 UI는 POST를 자동 재전송하지 않고 기록/커리어/시리즈를 다시 읽는다. 읽기에 실패하면 재조회 전까지 변경/다음 세트를 잠근다. 선택지를 누르는 것과 실제 전달 버튼을 구분한다.

## 경기 분석

세트별 양 팀 10명의 K/D/A, DPM, 딜 비중, 골드/비중, GD@15, CSD@15, KP, 평점, 폼/컨디션/멘탈 전후 기록을 표시한다. 패배 분석은 저장된 전력·상태·케미·전술·픽·메타·변동성의 상대 대비 기여 차이를 사용한다. 아직 기록하지 않는 로밍, 시야, 오브젝트 실패를 만들어서 표시하지 않는다. 현재 시뮬레이터의 집계 지표이며 실제 플레이 이벤트 로그는 아니다.

## 적용 및 검증

`1789682400000-intermission-feedback.ts`는 기존 기록을 유지하면서 효과 JSON 2개와 타입별 유일 인덱스를 추가한다. 한 세트 사이에 두 종류의 피드백이 존재하면 이전 스키마로의 롤백은 기록 보호를 위해 거부한다.

백엔드: `npm test -- --runInBand`, `npm run test:e2e:isolated -- app.e2e-spec.ts`.

프론트엔드: `npm run test:intermission`, `npm run test:match-flow`, `npm run test:match-report`, `npm run lint`, `npm run build`.

프론트 검증은 실제 컴포넌트의 렌더링/핸들러 검사이며 브라우저 시각 검증과는 구분한다. 보정 숫자는 알파 밸런스 값으로 추후 조정할 수 있다.
