# 선수 시장과 판매

## 화면

- 상단 **일반 시장**: 전체 선수 / FA 검색, 포지션·계약 상태 필터, 이적료 협상과 선수 계약 제안.
- 일반 시장 안의 **레전드 시장** 탭: 기존 레전드 공개 이벤트·영입 협상. 시즌 소식의 레전드 링크는 이 탭으로 직접 이동한다.
- **계약 → 소속 선수 선택 → 선수 팔기**: 구매 구단과 희망 이적료를 선택해 판매 제안. 판매 진행·철회는 여기에서, 전체 판매 내역은 일반 시장에서도 확인한다.
- 새 제안 연봉은 `10000만원 = 1억원`. 1만원씩 조정하며 `9999만원`, `1억 1만원`으로 표시한다(천 단위 쉼표 적용). 기존 계약·진행 중인 제안은 저장된 금액을 유지한다.

## 판매 처리

1. 커리어 소유권·재직 여부, 기존 이적시장 기간(11월 19일~12월 31일), 선수 소속을 검증한다.
2. 같은 포지션 후보가 없어도 주전을 판매할 수 있다. 구매 구단은 후보 자리가 있어야 하며 기존 계약 협상·판매가 진행 중인 선수는 중복 판매하지 않는다.
3. 희망 이적료는 기존 평가식의 평가액 이하, 기존 최소/최대 범위(5000~500000만원) 내 정수여야 한다. 구매 구단의 이적료·연봉 예산도 적용한다.
4. 구단 간 합의 뒤 구매 구단이 기존 AI 연봉 산정 규칙으로 선수와 계약 협상을 한다. 게임 날짜 1~3일 뒤 기존 계약 수락/거절 규칙을 적용한다. 사용자 대신 선수의 동의를 생략하지 않는다.
5. 계약이 성사될 때만 로스터·선수 소속·계약·이적 기록·AI 지출을 동일 트랜잭션에서 변경한다. 주전 판매 시 같은 포지션 후보가 있으면 승격하고, 없으면 해당 자리를 비운다. 감독 전력 변화 기록에도 공석을 반영한다. 감독은 새 선수를 영입하거나 보유 선수를 배치해 선발 5명을 채워야 경기를 진행할 수 있다. 영입 선수는 기존처럼 벤치에 합류한다.
6. 협상 철회·선수 거절·예산 부족·이적기간 종료·로스터 조건 변경 시 판매를 완료하지 않는다. 판매 대금은 기존 이적 기록에 남으며, 별도의 사용자 구단 현금 잔고 시스템을 추가한 것은 아니다.

AI는 여전히 사용자 구단 선수를 임의로 영입하지 않는다. 인증된 판매 요청만 계약 이력 첫 항목에 서버 전용 `USER_APPROVED_SALE` 동의를 기록한다. 요청 DTO로 이력을 받지 않으며, 계약 완료 시 동의와 원소속/구매 구단/선수/합의 상태를 다시 확인한다.

사용자가 타 구단 주전을 영입할 때도 원소속 구단의 후보 유무로 막지 않는다. AI끼리 자동 협상할 때의 후보 확보 판단과 방출 제한은 별도 정책으로 유지한다. 이적시장 날짜 자체를 정지시키는 기능은 아니므로 시장이 닫히기 전에 선수단을 보강해야 한다.

## API

| API | 목적 |
| --- | --- |
| `GET /careers/:id/transfers/market` | 전체 외부 선수·FA, 구단 요구 이적료, 합의 ID/실제 합의 금액 |
| `POST /careers/:id/transfers/agreements` | 기존 구단 간 영입 합의 |
| `POST /careers/:id/contracts/offers` | 기존 재계약·FA·이적 선수 계약 |
| `GET /careers/:id/transfers/sale-candidates` | 내 소속 선수 판매 평가액·이동 가능 여부 |
| `GET /careers/:id/contracts/sales` | 내 구단에서 승인한 판매 내역 |
| `POST /careers/:id/contracts/sales` | `{ careerPlayerId, buyerCareerTeamId, askingFee }` 판매 제안 |
| `POST /careers/:id/contracts/sales/:offerId/cancel` | 완료 전 판매 철회 |

금액 API 단위는 모두 정수 **만원**이다. UI의 억 표기를 API에 전달하거나 부동소수점 억 단위로 계산하지 않는다.

기존 테이블과 JSON 계약 이력을 사용하므로 이번 기능을 위한 마이그레이션·시드 재실행은 필요 없다. 기존 선수·커리어 데이터를 수정하거나 초기화하지 않는다.

## 검증

- `cd frontend; npm run test:market`: 금액 경계, 일반/레전드 시장 분리, FA/이적 요청, 중복 클릭, 실패 후 재조회, 화면 이탈, 판매·철회, 계약 화면 진입.
- 기존 `test:contracts`, `test:legends`, `test:app`도 함께 실행한다. 이 검사는 실제 컴포넌트 핸들러와 React SSR 기반이며 브라우저 시각 검사는 아니다.
- `cd backend; npm run test:e2e:isolated -- transfers.e2e-spec.ts`: 실제 격리 MySQL에서 소유권/입력 검증, 판매 완료·철회·중복 요청, 후보 승격, 예산 부족 롤백 및 기존 영입/방출/만료 동작 검증.
