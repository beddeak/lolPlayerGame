# 운영 AI 보완 — tactical-core-3

2026-09-27. 사용자가 선택한 **① 운영 AI 보완** 범위다. 기존 커리어 경기/API/DB/관전 UI는 교체하지 않는다. `simulation-v2`의 opt-in 개발 코어만 변경하며 카탈로그·커리어 원본 능력치·세이브를 수정하지 않는다.

## 재현한 문제

`sim:series --seed 125 --minutes 60 --best-of 5`의 첫 실제 드래프트(Malphite/Sejuani/Lucian/Ezreal/Soraka 대 Urgot/Hecarim/AurelionSol/Jinx/Hwei)를 같은 입력으로 추적했다.

- core-2에서는 60분에도 넥서스가 남았다. 사건 해시 `2fe4b9d8286271807a610a894094c7ce9e99d102e2ba55c8db4379ea0c69603d`를 재현했다.
- 억제기와 넥서스 포탑 일부를 파괴한 뒤에도 귀환 후 사이드 공성 경로가 살아 있는 다른 라인 포탑을 통과했다.
- 관측 경계의 작은 변화로 공성 라인을 반복 변경하고, 공성 중 정글러가 캠프 탐색/사냥으로 이탈했다.
- 오브젝트 합류 후 대기 계획이 유지되지 않았다. 기억에 남은 죽은 미니언 등 비챔피언도 미관측 적 지원군으로 계산했다.
- 합류 이동을 유지하는 최적화가 새 구조물 공격을 덮거나, 웨이브가 사라진 옛 경로를 그대로 따를 수 있었다. 별도 회귀 시나리오로 검사한다.

## 변경 내용

### 목표를 유지하되 위험하면 전환

- 공성 라인/대상은 최대 25초 기억한다. 약간의 점수 변화로 즉시 뒤집지 않되, 다른 라인의 큰 실제 압박·낮은 체력·포탑 위험·기지 방어·파괴된 대상은 재판단한다.
- 선택 라인이 바뀌면 `PLAN` 사건에 남긴다. 저장하는 것은 JSON 계획 메타데이터이며 전역 가변 캐시가 아니다.
- 후반 정글러는 충분한 장비나 진행 중인 공성/근접한 팀 합류가 있으면 웨이브 도착 전에도 합류한다. CS나 골드를 보정 지급하지 않는다.

### 안전한 공성 진입과 전환

- 이동 경로 전체를 현재 공개된 적 포탑 사거리와 비교한다. 안전한 지름길은 허용하고, 그렇지 않으면 선택한 라인의 실제 경유 지점과 우회 경로를 사용한다.
- 아군 미니언이 실제 포탑 사거리 안에 있는 경우만 보호된 경로로 취급한다. 이미 위험 원 안에 있는 선수의 바깥 방향 탈출은 허용한다.
- 공격 가능한 낮은 HP 구조물/공성 버프의 기회를 주변 챔피언 추격보다 먼저 평가한다. 사거리·시야·적법한 구조물 선행 조건과 실제 웨이브/체력 비교는 유지한다.
- 살아 있는 자기 팀 선수에게 바론/장로 버프가 있으면 새 먼 오브젝트 준비보다 공성 전환을 우선한다. 현재 공격 중인 오브젝트나 실제 사거리 내 Smite 기회는 예외다.
- 동일한 이동 경유 지점을 재사용하되 새 공격을 덮지 않고, 현재 웨이브/포탑 상태에서 경로가 안전한지 재확인한다.

### 오브젝트 준비·지속·포기

- 실제 이동 시간·건강한 합류 인원·현재 관측/마지막 관측 챔피언·모델 DPS와 생존 여력을 사용한다. 미니언/몬스터/죽은 유닛을 적 지원군으로 세지 않는다.
- 준비 계획에는 대상과 고정된 만료 시각을 남긴다. 이동→와드→대기가 매 판단마다 타이머를 리셋하지 않는다. 도착하면 합류를 기다린다.
- 기절/시전/와드 설치 중에는 실행할 수 없는 fallback 계획으로 기존 계획을 덮지 않는다. 이런 짧은 중단을 반복해 준비 제한시간을 연장할 수 없으며, 고정된 난수 소비 순서는 유지한다.
- 최대 30초 내 준비가 성립하지 않거나 싸울 여력이 부족하면 20초 재시도 유예 후 다른 행동을 한다.
- 시작 때의 인원/HP 기준을 살짝 밑돌아도 이미 공격 중이고 안전하게 마무리할 수 있다면 계속 공격한다. 아직 도착하지 않은 동료의 피해를 미리 가산하지 않는다.

## 구현 경계

- `battle-planner.ts`: 관측 기반 의도만 생성한다. 현재 숨은 적 HP/좌표, 숨은 오브젝트 HP를 읽지 않는다. 공개 구조물 상태/스폰 시각과 아군 정보만 추가로 받는다.
- `siege-routing.ts`: 벽과 포탑 위험을 고려한 물리 경유 지점 계산이다. 순간이동/구조물 피해/맵 변형을 하지 않는다.
- `contracts.ts`: 계획 메타데이터와 엔진 버전 3. 이전 개발 체크포인트는 명시적으로 거절한다.
- `engine.ts`: 공성 라인 전환 사건을 기록한다. 피해/이동/보상/넥서스 종료 판정은 기존 공통 Resolver 그대로다.
- `inspect-macro-lab.ts`: 지정 세트의 구조물·계획·관측 행동을 추적하는 DB 없는 진단 도구. 기본은 첫 세트, `--game 2` 등은 앞선 세트를 실제 종료한 뒤 진행하며 결과를 주입하지 않는다. `--verify-resume`은 최대 25분 시점의 JSON 체크포인트에서 재개해 전체 상태 해시를 비교한다.

룰 수치/챔피언 수치를 약화시키거나 특정 seed에 예외를 넣지 않았다. **시간 제한이면 여전히 승자 없이 멈춘다.**

## 실행

`backend`에서:

```powershell
npm test -- --runInBand
npm run test:sim:scenarios
npm run sim:series -- --seed 125 --minutes 60 --best-of 5
npm run sim:battle -- --seed 123 --minutes 60 --batch 3 --verify-resume
npx ts-node scripts/inspect-macro-lab.ts --seed 125 --minutes 60 --best-of 5 --verify-resume
npx ts-node scripts/inspect-macro-lab.ts --seed 125 --minutes 60 --best-of 5 --game 2
```

시리즈는 실제 3승 시 종료하므로 BO5를 일부러 다섯 세트로 만들지 않는다. 기본 검증은 짧은 회귀 테스트, 실제 경기 완주는 별도 CLI로 분리한다.

## 남은 범위

- 후보 합류는 관측 기반 예측이며 모든 선수에게 하나의 팀 오더를 원자적으로 배정하는 협동 계획기는 아니다. 개별 방어/교전/귀환이 합류보다 우선할 수 있다.
- 경로는 현재 모델 맵과 단순 포탑 위험 근사다. 실제 협곡의 모든 지형/스킬/카이팅/경쟁 팀 운영을 재현하지 않는다.
- 적은 seed에서 종료됐다는 사실은 모든 조합의 종료율·진영 균형·프로 수준 AI를 보증하지 않는다. 임의 시간 초과 승리로 정체를 숨기지 않는다.
- 기존 게임 화면에서 체감하려면 후속 STAGE 6의 경기 저장/관전 연결이 필요하다. 장시간 동기 시뮬레이션을 API 핸들러에 그대로 붙이지 않는다.
