# PHASE 22 — Legend Event

오프시즌(11/19~12/31)에 레전드 테마가 공개되고, 그 선수들을 FA 계약으로 영입한다.
공개만으로 사용자 구단에 지급하지 않는다. 같은 커리어의 AI 구단도 같은 선수를 먼저 영입할 수 있다.

## 사용 방법

1. 구단 사무실의 **레전드 시장**에서 지금까지 공개된 이벤트를 확인한다.
2. 오프시즌에 날짜를 진행한다. 공개 전에는 이벤트 개수·테마 선택·예정일을 알려주지 않는다.
3. 공개일에 달력/Fast Sim이 멈춘다. 시즌 허브의 **공개 내용 보기**로 시장을 연다.
4. 선수 카드를 선택하고 연봉·기간·역할·주전 보장 조건을 제안한다.
5. 기존 계약 화면에서 답변을 기다리고 최종 확정하면 후보 로스터에 합류한다.
6. 시즌 허브의 이벤트 **확인 완료**는 공개 알림을 닫는 동작이다. 계약 확정과 다르다.

AI가 먼저 영입하면 소속과 뉴스가 바뀐다. 진행 중이던 사용자 제안은 철회 처리하고 해당 응답 이벤트를
종료한다. 이후 필요하면 일반 이적시장에서 소속 구단과 다시 협상한다.

## 발생 규칙과 설정

설정: `backend/src/legends/config/legend-event.config.ts`

- 기본 0/1/2회 확률: **15% / 50% / 35%**.
- 직전 시즌 0회였다면: **5% / 55% / 40%**.
- 2시즌 연속 0회면 다음 시즌 최소 1회. 단, 아직 생성하지 않은 적격 카드가 있는 테마가 필요하다.
- 한 시즌 최대 2개 서로 다른 테마. 적격 테마가 1개뿐이면 최대 1회다.
- 기본 공개일 범위: **11/20~12/20**. 기존 계약 응답 시간을 남기기 위한 조정 가능한 초기값이다.
- AI 관심 구단: 전체 AI 구단 중 선수마다 최대 4팀, 공개 후 기본 **7~14일** 뒤 한 차례 경쟁한다.

공개 계획과 난수 seed는 커리어/연도별로 한 번 저장한다. 새로고침·재접속·같은 날 재처리로 다시 추첨하지
않는다. 연속 시즌 보정은 바로 전년도에만 이어진다. 적격 테마가 없는 상태에서 이미 계획이 확정된 시즌에
카탈로그를 나중에 추가해도 그 시즌은 재추첨하지 않는다.

기존 저장을 12월 말에 처음 연결하면 이미 지난 공개일의 이벤트는 현재 날짜에 처리한다. 이 경우에도
AI 대기 기간을 폐장일까지 줄여 공개 당일 빼앗지 않는다. AI 결정일에 시장이 닫혀 있으면 그 경쟁은
종료하고, 미계약 선수는 FA로 남는다. 사용자 신규 계약도 기존 규칙대로 같은 이적시장 안에서 확정해야 한다.

## 데이터와 중복 방지

- `Theme.legendEnabled=true`인 테마만 추첨 후보에 포함한다. 기존 테마 기본값은 false다.
- `LegendSeason`: 비공개 연간 계획, seed, 발생 횟수, 연속 미등장 기록.
- `LegendEvent`: 선택 테마, 카드 ID 스냅샷, 예정일/실제 공개일, 달력 연결.
- `LegendEventPlayer`: 실제 생성된 CareerPlayer, 관심 구단, AI 결정일/처리일.
- 원본 Player / PlayerCard의 스탯을 변경하지 않는다. 성장·팀 소속은 CareerPlayer에서 관리한다.
- 카드 능력치·나이·성격을 복사하고 기존 커리어와 같은 폼/컨디션/신뢰도·포지션/역할 숙련도를 초기화한다.
- 같은 PlayerCard는 동일 커리어에서 중복 생성하지 않는다. 계획 시와 공개 직전 모두 확인하고 DB unique로도 보호한다.
- 공개·AI 영입·협상 정리는 기존 커리어 잠금과 동일 DB 트랜잭션에서 처리한다.

`GET /careers/:careerId/legend-events`는 공개된 이벤트만 반환하는 소유권 보호 조회다.
잠재력, seed, 미래 개수/테마/예정일, AI 결정일은 응답에 없다. 조회로 추첨이나 영입을 실행하지 않는다.
일반 이벤트 목록에서도 예정 LEGEND_REVEAL은 숨기며, 공개 전 resolve 요청은 없는 이벤트처럼 404를 반환한다.

## 개발용 레전드 데이터

별도 생성 명령:

```powershell
cd backend
npm run migration:run
npm run seed:legends
```

원본: `backend/src/database/seeds/legend-demo.json`

실제 선수의 레전드 평가값은 아직 정하지 않았으므로 **명시적으로 이름에 DEMO가 붙은 가상 선수**를 사용한다.
2테마, 10선수, 10카드다. 기존 실명 선수와 커리어 저장을 덮어쓰지 않는다.
시드는 추가 전용이며 여러 번 실행해도 기존 카드의 스탯을 갱신하거나 중복 생성하지 않는다.
JSON을 수정해도 이미 같은 `(playerId, themeId, cardYear)`로 저장된 카드는 바뀌지 않는다.

실제 테마는 기존 카탈로그 관리자 API에서 `POST /themes`에 `legendEnabled: true`를 넣어 생성하고,
해당 themeId의 PlayerCard를 추가하면 된다. 일반 사용자의 카탈로그 쓰기 권한은 열지 않았다.

## 이번 단계에서 하지 않은 것

- PHASE 23의 일반 AI 로스터 운영, 난이도, 일반 FA/이적시장 전체 자동 운용.
- 아직 존재하지 않는 구단 예산 계좌 차감·명성 시스템. AI도 현재 구현된 선수 의사·팀 전력·계약 조건·후보 정원을 검사한다.
- 실제 레전드 선수 능력치 확정, 자동 사진 수집, 기존 구단/리그 정원 확장.
- PHASE 24 전체 시즌 캘린더 및 이후 팬·보드 시스템.

AI 연봉 등 초기 제안 조건은 `legend-ai.service.ts`의 `LEGEND_AI_CONTRACT_TERMS`에서 조정한다.
향후 경제/일반 AI 단계에서 확장할 수 있도록 기존 계약 확정 경로를 그대로 재사용한다.
