# 밴픽 AI 전략 다양화

## 적용 범위

실제 챔피언을 사용하는 DraftState v3의 자동 밴·픽, First Selection, 자동 포지션 배치에 적용한다. AI 구단 경기와 사용자 경기의 상대 AI/시간 초과 자동 선택이 같은 평가기를 사용한다. 기존 v1/v2 Variant 시리즈는 바꾸지 않는다.

백엔드 재시작 후 다음 자동 선택부터 적용된다. 이미 저장한 픽·밴·확정 배치·경기 결과는 다시 쓰지 않는다. seed 실행, DB 마이그레이션, 새 커리어 생성은 필요 없다.

## 여섯 가지 조합 방향

| 계획 | 우선하는 특성 |
| --- | --- |
| TEMPO | 초반 라인 압박, 정글·서포터 교전 개시 |
| TEAMFIGHT | 한타, 이니시, 앞라인 |
| SCALING | 후반 딜러와 이를 보호하는 서포터·정글 |
| POKE | 딜러의 사거리·라인 정리, 이를 받쳐주는 보호·교전 수단 |
| PICK | 중반 교전 개시와 피해량, 잘라먹기 |
| SPLIT | 사이드 캐리의 라인전·지속 성장·구조물 공격과 나머지 선수의 라인 정리 |

팀 전술, 선수 지시, 기본 능력치의 강점, 피어리스로 남은 선택지를 바탕으로 계획별 가중치를 정한다. 시리즈 seed·세트 번호·팀 ID로 한 세트의 방향을 고정한다. 밴 하나가 나올 때마다 무작위로 계획을 바꾸거나 새로고침으로 재추첨하지 않는다. 블루/레드 교환과 JSON 저장·복원에도 같은 팀의 계획이 유지된다.

이는 **밴픽 평가 방향**이며 구단의 저장된 전술이나 경기 엔진의 운영 AI를 덮어쓰는 설정이 아니다. 선수별 챔피언 숙련도를 임의 생성하지 않는다.

## 상황에 따른 선택

- 픽: 계획 적합도, 선수·지시 적합도, 부족한 조합 역할, 공개된 상대 픽과의 상성, 초반 멀티 포지션 가능성을 함께 평가한다.
- 상대의 강한 이니시에는 보호 수단, 앞라인에는 딜러의 피해·성장성, 긴 사거리에는 교전 개시 수단의 가치를 올린다. 서포터에게도 무조건 탱커를 때리는 딜러 역할을 요구하지 않도록 포지션별 반응을 구분한다.
- 밴: 상대 공개 픽으로 드러난 방향과 남은 역할, 대체 후보의 수·가치를 본다. 우리가 먼저 가져올 수 있는 핵심 픽을 직접 밴하는 비용도 반영한다. 상대의 내부 추첨 계획이나 아직 하지 않은 선택은 읽지 않는다.
- 최종 배치: 픽할 때 사용한 계획으로 5개 포지션을 배정한다. 사용자의 수동 배치는 그대로 허용한다. 추천 포지션은 AI의 선호이지 선택 금지가 아니다.
- First Selection: 우선 확보할 픽의 희소성과 선픽/후픽에 어울리는 계획을 비교한다. 모델에 없는 블루/레드 지형 보너스를 만들어 넣지는 않는다.
- 비슷한 점수의 상위 후보 안에서만 seed 기반 변화를 준다. 무관한 챔피언을 무작위로 뽑는 방식은 아니다.

30초 타이머, 20턴 밴픽 순서, 피어리스, 사용자 배치 확정, 소유권·동시 요청 검사 등 기존 규칙은 유지한다.

## 구현 위치

- `backend/src/drafts/draft-ai-strategy.ts`: 계획·포지션별 평가·안정적인 난수
- `backend/src/drafts/champion-draft-ai.ts`: 픽·밴·상대 대응·배치·First Selection
- `backend/src/drafts/champion-balance.ts`: 기존 32개 포지션 마스크 배정기에 선택적인 평가 콜백 추가. 기본 호출과 전투 능력치는 그대로 유지
- `backend/src/drafts/draft-state.ts`: 완료된 v3 밴픽의 자동 배치 연결
- `backend/src/drafts/champion-draft-ai.spec.ts`: 전략 차이·상대 대응·밴 기회비용·대체자 부족·불변성 등 회귀 테스트
- `backend/scripts/check-draft-ai.ts`: 반복 드래프트와 5세트 피어리스 검증

후보별 완전 탐색 트리는 만들지 않는다. 포지션 배정은 기존 32개 마스크 동적 계획법을 사용하고, 챔피언/포지션 점수는 평가 호출 안에서만 캐시한다. 순위와 판단 이유는 `rankChampionChoices`로 검사할 수 있으며, 현재 UI에 새로 표시하는 기능은 아니다.

## 재현 가능한 검증

`backend`에서 실행:

```powershell
npx jest --runInBand --testPathPatterns=champion-draft-ai.spec
npx ts-node scripts/check-draft-ai.ts
npx ts-node scripts/check-draft-ai.ts --seeds 100 --start-seed 25
npm test -- --runInBand
npm run build
npm run test:e2e:isolated -- --testPathPatterns=app.e2e-spec
```

배치 검사는 균형 전술·동일 선수 능력치로 시작해 선택의 다양성이 체급 차이 때문이 아님을 확인한다. 매 턴 재시도 동일성, 원본 상태 불변, 중복 없는 합법적인 20턴, 5개 포지션 배치, 별도의 5세트 50개 피어리스 픽을 검증한다. 입력 seed 범위는 명시적으로 제한한다.

수정 전 24개 seed에서는 챔피언 이름과 라인업은 달라도 전체 평균 초반 65.98 / 후반 88.77로 후반 위주였다. 변경 후 회귀 테스트는 TEMPO의 초반 성능이 SCALING보다 높고, SCALING의 후반 성능과 POKE의 사거리가 각각 비교 계획보다 높은지 실제 완성 조합으로 확인한다. 단순히 계획 이름만 달라지는 것을 통과 조건으로 삼지 않는다.

MySQL API 검증은 기존 개발 DB 대신 생성·삭제되는 임시 DB에서 수행한다. 마이그레이션·스키마 일치, 인증·소유권, 밴픽 순서, 시간 초과, 중복 요청, 배치 확정 후 경기 진행까지 확인한다. 브라우저 시각·청음 검증과는 구분한다.

### 2026-09-27 확인 결과

- 백엔드 전체 114개 suite / 1,493개 테스트 통과. 이 중 새 전략 회귀 테스트 14개.
- 24개 + 100개 seed, 총 124회의 양 팀 완전 자동 드래프트와 별도의 5세트 피어리스 검사 통과.
- 100개 seed에서 여섯 계획 모두 등장. 200개 팀 라인업 중 196개가 서로 달랐고 첫 픽 25종, 첫 밴 16종을 선택했다.
- 같은 배치에서 TEMPO는 초반 86.900 / 후반 72.929, SCALING은 초반 61.428 / 후반 92.324였다. POKE의 평균 사거리 59.222, TEAMFIGHT는 27.438로 실제 프로필 차이가 생겼다.
- 최종 배치 측정의 전체 20턴 자동 드래프트 평균은 24개 seed에서 39.218ms, 100개 seed에서 56.069ms였다. 공유 CPU에서 측정한 값으로 실행마다 변동하며 서비스 응답시간 보장은 아니다.
- 격리 MySQL E2E 6개 테스트, 스키마 검증 통과. 검증용 임시 DB 제거 확인.
- 프론트엔드 champion-draft / first-selection / match-flow 자동 검사, 백엔드·프론트엔드 빌드, 변경 TypeScript 파일 ESLint 통과. 프론트엔드 동작·스타일 변경은 없다.

## 남는 한계

- 챔피언 프로필은 기존 자체 밸런스 `prototype-2`다. 173개 챔피언의 실제 스킬과 패치 승률을 완전히 재현한 AI가 아니다.
- 계획별 장단점이 있으므로 포킹의 앞라인 부족, 피해 유형 편중 같은 약점이 남을 수 있다. 모든 팀이 같은 완벽 조합만 고르도록 강제하지 않는다.
- 특정 챔피언의 밴 빈도가 균등해야 하는 것은 아니다. 분포를 억지로 맞추기보다 현재 평가치에서 가치 있는 대상을 선택한다.
- 이번 검증은 전략 다양성·상황 대응·진행 무결성을 확인한다. 장기 실경기 승률 향상이나 메타 최적해를 증명한 것은 아니다.
