# PHASE 24 — 연간 시즌 달력

> 후속 변경: 국제대회는 이제 별도 대진·경기 저장 모듈로 연결했다. 주간 활동과 LCP/CBLOL 추가,
> 개발 DB 적용 대기 상태는 [후속 구현 문서](WEEKLY-ACTIVITIES-INTERNATIONALS.md)를 참고한다.
> 아래 검증 수치와 예약 기간 설명은 PHASE 24 완료 당시의 기록이다.

PHASE 23 AI 구단 운영을 기존 경기·이벤트·계약 흐름과 함께 연간 달력에 연결한다.
기존 저장의 날짜, 선수, 로스터, 경기 결과를 덮어쓰지 않는다.

## 사용 방법

시즌 허브의 **연간 리그 일정 연결** 버튼을 한 번 누른다.

- 해당 커리어의 자동 리그 배정을 활성화한다. 반복 요청해도 같은 연도·지역·스플릿이 중복 생성되지 않는다.
- 현재 또는 다음 국내 스플릿을 준비하며, LCK/LPL/LEC/LCS 중 최소 2개 팀이 있는 지역을 각각 생성한다.
- 이후 기존 날짜 진행 및 Fast Sim으로 다음 스플릿, 스토브리그, 다음 해 프리시즌이 이어진다.
- 다음 스플릿을 한꺼번에 미리 만들지 않는다. 앞선 성적을 참조해야 하는 시점에 실제 기록을 사용한다.
- 자동 배정을 켜지 않은 기존/커스텀 커리어는 수동 스플릿 생성을 유지한다.

조회만 하거나 마이그레이션을 적용하는 것만으로 자동 배정이 켜지지는 않는다.
시즌 연결 요청도 날짜를 진행하거나 경기를 시뮬레이션하지 않는다.

## 국내 리그 일정 배정

기존 `단계 × 28일` 방식 대신, 각 리그 포맷의 그룹/라운드 수 및 플레이오프 최대 라운드를
계산해 국내 리그 기간 안에 배정한다. 홀수 팀 수의 부전승, LPL 비대칭 그룹,
Swiss, Gauntlet, 더블 엘리미네이션의 추가 결승 가능성을 포함한다.

종속 라운드는 이전 라운드보다 뒤에 배치하며, 늦게 시작했지만 기간이 남아 있다면
경기 간격을 줄인다. 이미 저장된 경기의 날짜나 결과는 재배정하지 않는다.
기존 저장이 마감 후에 있거나 남은 라운드를 수용할 시간이 없다면 시간을 되돌리지 않고
앞으로 이어가되 `scheduleWarnings`로 지연을 표시한다. 이런 기존/지연 일정까지
무조건 국제대회 기간과 겹치지 않는다는 보장은 하지 않는다.

2팀 LCK Split 3처럼 한 팀짜리 조만 남아 경기 자체가 없는 단계는 부전승으로 다음 단계에
연결한다. 1팀 플레이인 참가자도 누락하지 않아 실제 2팀 플레이오프를 진행할 수 있다.
점수나 경기 결과를 임의로 생성하지 않는다.

미완료 이전 스플릿은 새 시즌으로 덮어쓰지 않는다. 실제 경기를 완료한 뒤 새 스플릿을 배정한다.
LCK/LPL Split 3은 같은 해 Split 2 완료 기록이 없으면 자동 생성하지 않는다.
팀 부족·미완료 이전 시즌·필요한 성적 누락은 `seasonReadiness`에 이유를 제공한다.
중간 시즌의 기존 저장에서 이미 지나간 미생성 스플릿을 임의로 채워 넣지 않는다.

## 날짜 진행과 기존 시스템

- `ONE_DAY`, `THREE_DAYS`, `NEXT_MATCH`, `NEXT_EVENT`는 더 가까운 시즌 경계에서 멈춘다.
- 이벤트가 없어도 `NEXT_EVENT`로 다음 시즌 구간까지 이동할 수 있다.
- 미완료 당일 경기와 사용자 결정 이벤트를 건너뛰지 않는다.
- 새 일정 생성 후 경기를 다시 조회해 생성 직후의 당일 경기 누락을 방지한다.
- Fast Sim은 AI 경기를 기존 방식으로 처리하고 사용자 경기, 결정 이벤트, 경기 처리 한도를 보존한다.
- 새로운 일반 구간 정지는 `SEASON_BOUNDARY`, 이적시장 개장/폐장 정지는 기존
  `TRANSFER_WINDOW_BOUNDARY`를 반환한다.
- 12/31의 미완료 영입 종료, 1/1의 연도 갱신, 계약 만료, AI 예산 이월은 기존 경로를 사용한다.
- 연도만 바뀌었다고 선수 카탈로그·현재 스탯·나이·잠재력·로스터를 초기화하지 않는다.

시즌 구간은 날짜에서 계산한다. 매년 같은 달력 안내 이벤트를 DB에 반복 생성하지 않으므로
GET이나 같은 날짜 재호출에 의해 시즌 경계가 중복되지 않는다.

## API / 구조

```text
GET  /careers/:careerId/calendar
POST /careers/:careerId/calendar/start-season
POST /careers/:careerId/calendar/advance
```

기존 달력 응답에 다음 필드가 추가된다.

```text
autoSchedule
season.year / currentPhase / nextPhase / nextBoundaryDate / periods
seasonReadiness[]
scheduleWarnings[]
```

소유권 확인과 커리어 잠금 안에서 자동 배정 및 스플릿 생성이 실행된다.
수동 생성 API도 동일한 잠금·생성 경로를 사용하며, 기존 중복 생성 요청은 계속 409를 반환한다.
`Calendars → SeasonSchedule → Leagues` 구조이며, `EventQueue → Leagues` 순환 의존성을 만들지 않는다.

## 마이그레이션

`AddFullSeasonCalendar1788818400000`은 `careers.autoSchedule`만 추가한다. 기본값은 `false`다.

기존 저장 삭제나 seed 재실행은 필요 없다.

## 명시적인 범위 밖

- First Stand/MSI/Worlds는 **달력상 개최 기간만 예약**한다. 실제 국제대회 경기 엔진,
  진출팀 결정, 국제 로스터 등록/출전 제한은 아직 없다. 가짜 경기 결과나 진출팀을 만들지 않는다.
- 시즌 리뷰 기간은 기존 리그 성적을 확인하는 구간이다. 팬 평가·이사회 평가·해고는 PHASE 25다.
- 새 Scrim 엔진, 나이 상승·은퇴·성장 정책, 새로운 재정·트레이드 시스템은 추가하지 않는다.
- 2팀 개발 데이터가 실제 10/16/10/8팀 정규 리그 로스터를 대체하는 것은 아니다.

## 검증

2026-09-13 검증 결과:

- 백엔드 **51 suites / 486 tests** 통과.
- 실제 격리 MySQL **6 suites / 45 tests**, 최종 전체 검사를 새 DB에서 **2회 연속 통과**. 매 실행마다 빈 DB에 26개 마이그레이션 적용,
  엔티티/스키마 일치 검증, 테스트 후 해당 임시 DB 제거.
- 4개 지역 각각 2팀/정규 팀 수로 3개 스플릿의 **24개 동적 대진 진행 경로** 검증.
- 새 실제 API 테스트에서는 8개 구단으로 2026년 **12개 지역 스플릿을 모두 완주**하고,
  14개 시즌 구간을 거쳐 2027년 1월 1일의 다음 시즌 4개 리그 생성까지 검증.
- 위 API 경로의 모든 경기는 국내 기간 안에 있고, 같은 팀의 같은 날짜 중복 경기가 없음.
- 새해 전환 시 CareerPlayer·Roster·기존 PlayerContract를 비교해 유지 확인,
  AI 구단 7개 예산의 연도 갱신 및 이적 지출 초기화 확인.
- 동시 시작 요청 3회, 타 계정 접근, 조회 무변경, 늦은 기존 저장, 성적 누락,
  사용자 결정 이벤트의 정지/재개 검증.
- 프론트 **65개 검사** 통과: 기존 44개 + 달력 21개. 이전 요청·세션 응답 차단,
  중복 클릭 방지, 다년차 탭 구분과 선택 유지 포함.
- 양쪽 타입 검사·lint·production build 통과. Vite의 sandbox `spawn EPERM`은 승인된 재실행으로 검증.
- 프론트 검사는 SSR/모의 hook/API 기반이며 **실제 브라우저 클릭 검증은 하지 않았다**.
- 개발 DB의 26번째 마이그레이션 적용 및 스키마 일치 확인. 신규 플래그를 제외한 기존 테이블
  데이터 해시가 적용 전후 동일했다: 커리어 6개, 구단 20개, 선수/로스터 각 104개,
  리그 10개, 단계 26개, 경기 24개, 기존 이벤트/계약 및 카탈로그 포함.

실제 DB 테스트에서 발견한 대진 역방향 관계 미로딩 오류도 수정했다. 다음 경기 날짜를 정할 때
`fixture.leagueStage`가 로딩됐다고 가정하지 않고 이미 조회된 단계와 경기 배열을 사용한다.
